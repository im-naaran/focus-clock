# 需求规格：WiFi 远程设置

日期：2026-08-07
Feature：wifi_remote_settings
阶段：Phase 1
来源：`docs/wifi-remote-settings.md` 与当前代码审查结果

## 背景与目标

为 Focus Clock 增加由本机显式开启的 SoftAP 配置门户，以及独立的外部 WiFi 联网策略。用户应能通过手机设置现有设备配置和 STA 凭据，同时保持配置门户的生命周期完全由本机控制。

本阶段只提供可复用的 WiFi 基础设施、配置门户和状态展示，不实现 NTP 或其他联网业务。

## 功能需求

### 配置模式生命周期

R-01：设备重启后 WiFi 配置模式必须默认关闭，且配置模式运行态不得持久化。

R-02：SETTING 必须新增 `WIFI CONFIG` 入口；只有本机确认操作可以启动配置模式。

R-03：配置模式启动后必须提供无密码的开放 SoftAP 和 HTTP 配置服务，并停留在专用 OLED 页面。开放 AP 只在用户从本机明确开启配置模式后存在。

R-04：配置模式优先级必须高于外部联网策略。策略为 `OFF` 或空闲 `AUTO` 时，仍必须为配置门户临时开启 AP。

R-05：保存远程配置、HTTP 客户端断开或长时间无交互均不得自动退出配置模式。

R-06：只有专用 OLED 页面中的物理 Cancel 操作可以停止 HTTP、关闭 SoftAP 并返回 SETTING 菜单；远程 API 不得提供退出接口。

R-07：配置模式运行期间 OLED 不得自动息屏，现有主动 Light Sleep 必须被禁止。

R-08：OLED 配置流程必须先显示开放 AP 名和连接提示；检测到至少一个 SoftAP 客户端后，自动切换为清晰的完整访问网址和物理 Cancel 提示，不显示 QR，也不要求用户再次按 Confirm。所有内容必须来自同一网络配置源。

### WiFi 联网策略

R-09：持久化策略只包含 `OFF` 和 `AUTO`，默认 `OFF`；不提供持续联网的 `ON`。未知持久值必须回退为 `OFF` 并记录日志。

R-10：`OFF` 在配置模式之外必须断开 STA 并关闭 WiFi 无线功能。

R-11：`AUTO` 平时必须关闭 WiFi；只有功能、业务或定时任务显式申请联网时，才开启 STA、使用已保存凭据连接并在任务需要的期限内重连。任务释放联网需求后必须断开 STA 并关闭无线。

R-12：`AUTO` 必须独立保存。本阶段除一次性连接测试外没有自动联网业务，空闲运行行为与 `OFF` 相同；代码必须提供未来任务申请和释放网络的明确扩展入口。

R-13：目标模式必须按运行需求决定：无配置模式且无 AUTO 任务为 `WIFI_OFF`；无配置模式且 AUTO 任务活动为 `WIFI_STA`；配置模式且无 STA demand 为 `WIFI_AP`；配置模式且 AUTO 任务、一次性连接测试或 Portal 异步扫描形成 STA demand 时为 `WIFI_AP_STA`。扫描和连接测试允许在持久策略为 `OFF` 时临时申请 STA；配置 AP 不得因扫描或 STA 失败而停止，临时 demand 结束后必须恢复 `WIFI_AP`。

R-14：在配置模式中保存策略后应立即协调目标模式。`OFF` 或没有联网任务的 `AUTO` 都只保留配置 AP；单纯保存 `AUTO` 不得隐式形成持续 STA 连接。

R-15：配置模式或 AUTO 联网任务活动期间必须阻止当前的主动 Light Sleep，确保 SoftAP、HTTP、物理 Cancel 和联网任务持续运行；两者都结束后恢复现有睡眠策略。

R-16：AUTO 联网任务活动且 STA 成功连接时，主要 OLED 页面底部显示 WiFi 图标；任务结束或未连接时不显示连接成功图标。

### 持久化与凭据

R-17：必须持久化 WiFi 策略、STA SSID 和 STA 密码，并兼容旧设备不存在这些 key 的情况。配置页必须提供独立的“清空 WiFi 配置”按钮，确认后同时清除已保存的 SSID 和密码，但不得隐式修改独立的 `OFF/AUTO` 策略。

R-18：SSID 必须按 UTF-8 字节数校验，最大 32 字节；STA 密码允许为空。非空密码必须按框架实际支持的 WPA/WPA2 密码规则校验。

R-19：HTTP 响应和串口日志不得返回或打印已保存的明文 STA 密码。普通保存规则为：SSID 为空时忽略提交的密码并清除现有 SSID/密码；SSID 非空时更新 SSID，若与旧值相同可跳过写入；此时密码为空表示保留原密码，密码非空表示更新密码。独立的“清空 WiFi 配置”按钮执行相同的 SSID/密码清除语义。

R-20：远程保存必须先校验完整请求，再写入 RTC、NVS 和运行态；校验失败时不得应用任何字段。

R-21：NVS 写入失败必须返回明确错误，不得把未成功持久化的配置报告为保存成功；多 key 部分写入的恢复语义须在设计中定义。

### 本机设置与状态

R-22：SETTING 必须新增 `WIFI CONFIG` 和 `WIFI` 两项，并在 128x64 OLED 上提供可辨识的五项菜单导航，不得因新增项丢失现有设置入口。

R-23：`WIFI` 编辑页必须允许旋钮选择 `OFF` 或 `AUTO`，确认后持久化并应用，Cancel 放弃未确认变更。

R-24：在 SETTING 菜单选中 `WIFI CONFIG` 并按一次物理 Confirm 后必须立即请求配置模式，直接显示 AP 启动/手机连接页面；不得再显示 `START OPEN AP?` 或要求第二次 Confirm。菜单选择本身即为明确的本机启动动作。

R-25：专用配置页面必须持续展示配置模式运行状态，且物理 Cancel 在 HTTP 请求或 WiFi 状态变化期间仍应可靠响应。

### Web 页面与 HTTP API

R-26：配置门户必须提供不依赖外部 CDN、字体或脚本的内嵌页面，并适配常见手机窄屏。页面源码必须作为独立 `.html` 文件维护，不得把 HTML/CSS/JS 主体直接写在 C/C++ 头文件中；构建时由 PlatformIO 直接嵌入固件。

R-27：页面必须读取并编辑亮度、RTC 时间、夜间息屏开关与起止时间、`OFF/AUTO` WiFi 策略、SSID 和密码。

R-27A：亮度必须使用可见当前值的选择框，提供 `1 - 最暗` 至 `5 - 最亮` 五档标记，不使用无法直接看到数值的拖动条。

R-28：页面必须提供“使用当前浏览器时间”，提交浏览器本地年月日时分秒；设备不得再次应用时区偏移。

R-29：RTC 默认只读。只有用户在本机或远程设置页明确提交时间，以及未来已确认的自动对时服务，才允许写入 DS1302；设置页提交的合法时间可用于修复当前无效的 RTC，写入后必须强制刷新状态并报告真实结果。

R-30：页面必须按用户操作触发 WiFi 扫描，展示 SSID、RSSI 和是否加密，并允许选择 SSID 填入表单。结果超过 20 个时必须保留去重后 RSSI 最强的 20 项，不得仅保留驱动返回的前 20 个不同 SSID。

R-31：WiFi 扫描必须使用框架异步扫描能力，不得阻塞设备主循环；扫描开始前由 WiFi service 临时申请 STA 接口并协调到 `WIFI_AP_STA`，但不得因扫描 demand 调用 `WiFi.begin()` 或连接已保存的外部 AP。扫描结果提取或失败后释放该 demand 并恢复 `WIFI_AP`；扫描期间物理 Cancel、Timer/RTC 更新和 HTTP 轮询仍须运行。

R-32：配置 API 至少提供读取配置、保存配置、启动/查询异步扫描和启动/查询一次性连接测试的能力；具体路径与响应在设计阶段确定。

R-33：读取配置必须返回非敏感配置和 WiFi 运行状态，包括策略、SSID、是否已配置密码、连接状态及可公开 IP；不得返回密码本身。

R-34：保存成功后配置门户必须继续运行，并向页面返回逐字段一致的成功结果；一次性连接测试或 AUTO 任务引起的 STA 信道切换若造成短暂 AP 中断，页面应给出可恢复的状态。

R-35：API 必须验证 Content-Type、请求体长度、字段类型、枚举、数值范围、时间合法性和字符串字节长度，并使用一致的 4xx/5xx JSON 错误结构。handler 必须将超过 1024 字节的请求拒绝为 `413`，且超限或非法请求不得修改配置。内置同步 `WebServer` 在 handler 之前解析表单，因此该长度检查不声明为解析前内存上限；如需严格限制恶意客户端的解析前分配，必须单独替换 HTTP parser。

R-36：配置服务只能在配置模式运行时接受请求。任何已连接 Focus Clock SoftAP 的客户端均可访问；请求若经 ESP32 的 STA 接口到达则必须拒绝，不能因 `AP_STA` 默认监听而暴露到 `10.0.x.x` 等外部局域网。

### 显示与配置集中化

R-37：AP 地址、网关、子网、信道、SSID 生成规则、开放 AP 设置、STA 重连参数和长度限制必须集中在 `config_network.h` 或等价配置模块。

R-38：配置页面入口、OLED 网址文本和 SoftAP 实际配置必须由同一来源派生，不得重复硬编码 `192.168.4.1`。

R-39：OLED 必须完整、清晰地显示配置网址，不得裁剪；允许分行显示协议和地址，但组合后必须明确为 `http://192.168.4.1/`。

R-40：WiFi 图标的 bitmap 绘制必须与现有整行缓存协调，图标出现/消失和页面切换后不得残留或被错误擦除。

R-41：一次性连接测试只能使用已经成功持久化的 SSID/密码，不接受请求内临时凭据。页面存在未保存的 WiFi 字段修改时必须禁用测试；保存成功且 SSID 非空后才允许启动。

R-42：一次性连接测试在配置模式内临时申请 STA，即使策略为 `OFF` 也允许；测试期间保持 SoftAP，返回连接中、成功、失败或超时状态，结束后释放 STA 并恢复 `WIFI_AP`，不得修改持久化策略。

R-43：启动一次性连接测试前，页面必须明确提示 `WIFI_AP` 可能因 STA 信道切换而短暂不可用，并提示用户不要刷新或关闭页面。测试期间必须禁用保存、清空、扫描和重复测试操作，并使用浏览器 `beforeunload` 等能力尽力提示刷新或退出风险。

R-44：设备端必须持有权威的连接测试状态，不能依赖单次页面会话。页面请求失败时应显示 AP 暂时不可用并自动重试；用户重新连接 AP 或刷新页面后，页面必须能重新查询当前/最近一次测试状态，不得要求测试任务仍依赖原页面继续运行。

R-45：“清空 WiFi 配置”必须要求一次明确确认；成功后页面清空 SSID/密码输入状态、将 `passwordConfigured` 更新为 false，并禁用一次性连接测试，直到新的非空 SSID 成功保存。

## 非功能需求

NFR-01：WiFi 和 HTTP 处理必须保持主循环协作式运行，不使用长时间阻塞等待或无限重试。

NFR-02：优先复用 Arduino ESP32 内置 `WiFi`、`WebServer` 和现有 Preferences / RTC / display 能力；新增依赖必须在设计中说明必要性并获得确认。

NFR-03：不得破坏 CLOCK、TIMER、现有 SETTING、夜间息屏、输入唤醒和 RTC 自动初始化行为。

NFR-04：开放 SoftAP、STA 密码明文 NVS 和 HTTP 无 TLS 的安全限制必须在文档中明确；默认日志不得泄漏 STA 密码。

NFR-05：网络状态机必须使用溢出安全的 `millis()` 截止时间比较，不得通过 `delay()` 实现重连调度。

NFR-06：首次版本应避免动态构造大型 `String` 造成堆碎片；页面资源和响应缓冲需在设计中给出边界。

NFR-07：实现应补充可在无 WiFi 硬件交互下验证的纯逻辑测试或最小宿主脚本，至少覆盖模式决策、输入校验、策略持久值和 API 字段规则；`pio run` 不能作为唯一验证。

## 验收标准

AC-01：旧设备升级后默认 `WIFI=OFF`、配置模式关闭，现有配置仍可读取。

AC-02：本机确认开启后，手机无需密码即可按 OLED 显示的 `FocusClock-xxxx` SSID 连接 AP，并通过随后清晰显示的完整网址打开配置页面。

AC-03：保存任意合法配置后页面和 AP 继续运行，直到本机物理 Cancel。

AC-04：本机物理 Cancel 在扫描、STA 连接失败或页面有活动客户端时仍能退出配置模式。

AC-05：`OFF`、`AUTO` 可独立保存并在重启后恢复；配置模式和 AUTO 任务形成的四种 AP/STA 目标模式符合需求。

AC-06：保存非空 SSID 后可以启动一次性连接测试；测试期间页面提示可能的 AP 短暂中断并在请求失败后自动恢复轮询，错误 STA 密码不会永久关闭配置 AP，修正并再次保存后可重新测试。

AC-07：配置模式或 AUTO 联网任务活动期间当前主动 Light Sleep 不会启动；全部结束后恢复现有睡眠策略。

AC-08：配置读取不泄漏 STA 密码，非法或超限请求不会部分修改运行配置。

AC-09：WiFi 扫描期间设备输入和周期状态更新保持可响应。

AC-10：远程页面能更新亮度、RTC、夜间息屏和 WiFi 配置；RTC 无效时也能用合法浏览器时间修复。

AC-11：配置服务在 `AP_STA` 下不能从 STA 局域网接口访问。

AC-12：完整配置网址和 WiFi 图标在真机 OLED 上清晰、无残影；客户端接入和断开后的页面切换不留下陈旧内容。

AC-13：新增逻辑测试通过，且 `pio run` 完成构建；硬件结果仍需用户人工确认后才能标记验证通过。

AC-14：点击“清空 WiFi 配置”并确认后，已保存 SSID/密码均被清除，`OFF/AUTO` 策略保持不变，测试按钮不可用。

## 范围外

- NTP/SNTP 自动授时及最后同步时间。
- `AUTO` 策略的具体联网任务和调度。
- 配置模式之外通过家庭局域网访问设置页。
- Captive portal、DNS 劫持、连接后自动弹出网页、HTTPS、用户账户和复杂认证。
- STA 密码加密存储。
- 通用 sleep blocker 任务系统及 WiFi 低功耗深度优化。
- OTA、文件上传和外部业务数据获取。

## 对概念方案的审阅结论

整体分层方向合理：配置模式与联网策略解耦、配置模式不持久化、AP 优先、`AUTO` 保留独立枚举、网络常量集中化、NTP 独立拆分，这些决定应保留。

以下内容需要修正或补充后才能进入设计：

1. 概念稿建议第一版同步扫描，但这会阻塞当前单线程主循环并可能漏掉物理 Cancel，因此已确认改为框架原生异步扫描。
2. `WebServer` 在 `AP_STA` 下可能同时暴露于 STA 接口，不能仅凭“本地 AP 使用”的文字保证边界。
3. 需求已改为开放 SoftAP，并在检测到客户端加入后自动切换 OLED 显示完整文本网址；不再显示 QR，不实现 captive portal。
4. 持续联网的 `ON` 策略已删除，只保留 `OFF/AUTO`；配置模式和 AUTO 任务活动期间禁止当前主动 Light Sleep。
5. GET 配置不能回显密码；普通保存时空 SSID 表示清除 SSID/密码，非空 SSID 配合空密码表示保留旧密码；独立“清空 WiFi 配置”动作也同时清除 SSID/密码。
6. AP SSID 后缀生成规则、密码展示、API 错误、NVS 部分失败和 STA/AP 信道切换均未定义。

## 决策确认记录

Q-01（已确认）：使用异步 WiFi 扫描，以“启动扫描 + 轮询状态/结果”保持主循环和物理 Cancel 响应。

Q-02（已确认）：所有 SoftAP 客户端均可访问；通过 ESP32 STA 接口从 `10.0.x.x` 等外部局域网到达的请求必须拒绝。

Q-03（已变更确认）：采用两阶段 OLED；客户端接入开放 AP 后自动显示完整文本网址，不再显示 QR。不实现 captive portal 或手机自动弹页。

Q-04（已确认）：删除持续联网的 `ON`，只保留 `OFF/AUTO`。配置模式或 AUTO 联网任务活动期间禁止当前主动 Light Sleep，活动结束后关闭 WiFi 并恢复睡眠策略。

Q-05（已确认）：GET 不返回密码。普通保存时 SSID 为空清除 SSID/密码；SSID 非空时更新 SSID，密码为空保留原密码，密码非空更新密码。页面另提供独立清空按钮执行相同清除动作。

Q-06（已确认）：配置 AP SSID 使用 `FocusClock-` 加设备 MAC 后四位十六进制；SoftAP 不设置密码。

Q-07（已确认）：RTC 默认只读；只有本机/远程设置页的显式保存以及未来自动对时可以写 RTC。设置页可用合法输入修复无效 RTC。

Q-08（已确认）：提供一次性连接测试，但只能测试已成功保存的配置。页面存在未保存 WiFi 修改时禁止测试；测试在保持 SoftAP 的同时临时进入 `WIFI_AP_STA`，完成后回到 `WIFI_AP`。

Q-09（已确认）：页面增加独立“清空 WiFi 配置”按钮，明确确认后同时清除 SSID/密码；需要从有密码网络切换到开放网络时，先清空配置，再保存新的 SSID 和空密码。

## 待确认问题

无。

# 需求规格：OLED 空闲息屏

日期：2026-06-16
Feature：oled_idle_screen_off
阶段：Phase 1
来源：`power-optimization-roadmap.md`、当前代码检查结果。

## 背景与目标

当前固件已经在 CLOCK 页面空闲时进入 Light Sleep，但 OLED 在 Light Sleep 期间仍保持点亮，可能成为电池供电场景的主要耗电来源。

本功能目标是在夜间时间段内，当设备停留在 CLOCK 页面且用户无操作时关闭 OLED 显示输出；用户任意操作应先点亮屏幕并重绘当前页面，避免第一次唤醒输入同时触发业务动作。

该功能应保持应用状态、计时器、RTC 服务和输入状态机语义稳定，只新增屏幕电源管理能力。

## 功能需求

### 配置与默认值

R-01：固件应支持夜间息屏启用开关，默认启用。

R-02：固件应支持夜间关闭时间，默认 `20:00`。

R-03：固件应支持夜间开启时间，默认 `08:00`。

R-04：夜间时间段应支持跨午夜区间；当关闭时间晚于开启时间时，`20:00 -> 08:00` 表示当天 20:00 到次日 08:00。

R-05：夜间时间段也应支持同日普通区间；当关闭时间早于开启时间时，区间表示同一天内的关闭窗口。

R-06：当关闭时间等于开启时间时，应视为没有夜间息屏窗口，避免全天关闭屏幕。

R-07：固件应支持手动唤醒后的最短亮屏窗口，默认 60 秒。

### OLED 显示开关

R-08：显示层应提供 OLED 关闭能力，关闭时发送 SSD1306 display off 命令 `0xAE`。

R-09：显示层应提供 OLED 打开能力，打开时发送 SSD1306 display on 命令 `0xAF`。

R-10：OLED 打开后应使显示缓存失效，并要求主循环重绘当前页面。

R-11：OLED 显示开关不得改变 brightness/contrast 设置；`displaySetContrast(...)` 与 OLED 开关语义应保持独立。

R-12：OLED 关闭只应关闭显示输出，不应清空应用状态、计时器状态、RTC 调度或输入状态机。

### 自动息屏条件

R-13：只有 `AppMode::Clock` 允许自动息屏。

R-14：`AppMode::Timer` 不允许自动息屏，即使当前 Timer 未运行。

R-15：`AppMode::Setting` 及所有 SETTING 子状态不允许自动息屏。

R-16：RTC 无效或当前 RTC 时间无效时，不得执行夜间自动息屏。

R-17：夜间息屏开关关闭时，不得自动关闭 OLED。

R-18：当前分钟不在夜间息屏区间内时，不得自动关闭 OLED。

R-19：存在待渲染内容时不得自动关闭 OLED。

R-20：任意按钮按住时不得自动关闭 OLED。

R-21：输入消抖等待期间不得自动关闭 OLED。

R-22：输入反馈仍活跃时不得自动关闭 OLED。

R-23：Light Sleep 唤醒保持窗口仍活跃时不得自动关闭 OLED。

R-24：手动唤醒保护窗口未结束时不得自动关闭 OLED。

R-25：满足自动息屏条件后，应关闭 OLED，并记录屏幕当前为关闭状态。

### 自动亮屏条件

R-26：当设备运行到夜间息屏区间结束后，如果 OLED 处于关闭状态，应自动打开 OLED。

R-27：自动打开 OLED 后应重绘当前页面。

R-28：RTC 从无效恢复为有效时，如果当前不在夜间息屏区间且 OLED 处于关闭状态，应打开 OLED 并重绘。

R-29：当用户进入 TIMER 或 SETTING 时，如果 OLED 处于关闭状态，应打开 OLED 并重绘。

### 输入唤醒与拦截

R-30：OLED 关闭期间，Mode、Confirm、Cancel 按钮、旋钮旋转或旋钮按压的第一次输入应只点亮 OLED，不执行原本业务动作。

R-31：OLED 关闭期间，普通输入队列中的事件和 Light Sleep 唤醒桥接产生的 pending button 都必须经过同一套息屏输入拦截。

R-32：OLED 关闭期间触发输入唤醒后，应设置手动唤醒保护窗口到当前时间加 60 秒。

R-33：输入唤醒 OLED 后应标记显示需要重绘。

R-34：OLED 关闭期间的输入唤醒不应绕过 Mode 长按状态机；Mode 长按可靠性仍由 `input.*` 和 `sleep_manager.*` 管理。

R-35：OLED 点亮期间，输入应按现有逻辑正常分发。

R-36：OLED 点亮期间，任意业务输入应刷新最近用户输入时间。

R-37：旋钮 `KnobRaw`、`KnobRotationStart`、`KnobRotationEnd` 和 `KnobStep` 都应被视为用户活动。

### 状态记录

R-38：固件应记录当前屏幕是否点亮。

R-39：固件应记录最近一次用户输入时间。

R-40：固件应记录手动唤醒保护窗口截止时间。

R-41：固件应记录最近一次屏幕电源状态变化时间，用于调试和防止边界抖动。

### 持久化

R-42：夜间息屏启用开关、关闭时间和开启时间应持久化到 ESP32 NVS / Preferences。

R-43：旧设备没有夜间息屏配置时，应使用默认值，不影响启动。

R-44：保存夜间息屏设置失败时，不应阻断 CLOCK/TIMER 核心功能，但应通过串口日志可见。

R-45：夜间时间设置不应保存到 DS1302 RTC。

### SETTING 页面

R-46：SETTING 菜单应新增夜间息屏配置入口，建议显示文本为 `NIGHT OFF` 或 `SCREEN OFF`。

R-47：夜间息屏配置子页面应至少支持修改启用开关、关闭时间和开启时间。

R-48：时间编辑应支持小时和分钟字段，小时范围 `0..23`，分钟范围 `0..59`。

R-49：SETTING 页面和夜间息屏配置子页面应始终保持 OLED 点亮。

R-50：夜间息屏配置的保存策略应避免旋钮连续变化造成过多 NVS 写入。

R-51：新增 UI 文本必须使用英文 ASCII，并适配当前 OLED 字符宽度限制。

### 调试与测量

R-52：在启用串口日志的构建中，应能输出 OLED 自动关闭、自动打开、输入唤醒和配置保存失败等关键事件。

R-53：默认电池构建或当前 `ENABLE_SERIAL_LOGGING == false` 时，不应输出串口日志。

## 非功能需求

NFR-01：实现应延续现有模块边界，优先在显示、电源状态、输入分发、持久化和 SETTING 模块中小范围改动。

NFR-02：不得更改硬件接线、GPIO 分配或 PlatformIO 目标环境。

NFR-03：不得引入新的外部依赖。

NFR-04：主循环中不得引入长时间阻塞等待。

NFR-05：屏幕电源状态逻辑应能正确处理 `millis()` 回绕。

NFR-06：自动息屏不得降低 Timer 运行准确性。

NFR-07：自动息屏不得改变 RTC 正常读取调度策略。

NFR-08：OLED 关闭期间应继续允许 Light Sleep 定时唤醒，以便 RTC 服务更新并判断夜间结束。

## 验收标准

AC-01：默认配置下，`20:00` 到次日 `08:00`，停留在 CLOCK 页面且无用户操作时 OLED 会自动关闭。

AC-02：`08:00` 到达后，如果设备仍在运行，OLED 会自动恢复点亮并重绘 CLOCK 页面。

AC-03：RTC 无效时不会执行夜间自动息屏。

AC-04：TIMER 页面不会自动关闭 OLED。

AC-05：SETTING 页面及夜间息屏配置子页面不会自动关闭 OLED。

AC-06：OLED 关闭时按 Mode、Confirm、Cancel、旋转旋钮或按下旋钮，只点亮屏幕，不执行原本业务动作。

AC-07：OLED 被操作点亮后，如果仍在夜间区间且停留在 CLOCK 页面，60 秒无操作后会再次关闭。

AC-08：OLED 被操作点亮后，如果用户切到 TIMER 或进入 SETTING，屏幕保持点亮。

AC-09：亮度设置和 OLED 开关互不覆盖；息屏后亮屏仍保持用户设置的亮度档位。

AC-10：修改夜间息屏启用开关、关闭时间和开启时间后，重启设备仍能保留设置。

AC-11：旧设备没有夜间息屏配置时，启动后使用默认配置，不出现配置读取错误导致的功能中断。

AC-12：`pio run` 能完成构建。

## 范围外

OOS-01：Timer 运行时 Light Sleep。

OOS-02：短按唤醒可靠性专项优化，例如改用 ESP32 GPIO wake status。

OOS-03：电池构建配置拆分。

OOS-04：Preferences 空闲关闭策略。

OOS-05：GPIO 低功耗审计和硬件供电路径审计。

OOS-06：夜间自动降低亮度但不息屏的策略。

OOS-07：声音、蜂鸣器或其他提示硬件。
